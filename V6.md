# V6: the whole chain trained at test density, with collective sibling evidence and a second cross-encoder

V6 replaces everything after the V2 feature tables. It starts from the cache you already have: the V2 features, the
V3 XLM-R scores and the phase-2 decisions. V5 was never run, so V6 includes the useful V5 pieces itself. One command
runs it: `bash run_all.sh --stage v6all`. The submission is chosen by rules fixed in advance (§6). Everything in V6
passed an end-to-end CPU test on synthetic data (`bash code/v6/tests/smoke_v6.sh`). That test runs the exact runner
commands of all 35 V6 steps. **Nothing in V6 has run on the real data yet.**

## 0. What changes compared with what you ran (V2 → V3 → V4 / phase 2)

| part | V2 / V3 / V4 (your runs) | V6 |
|---|---|---|
| training universe | SIM19: 19 % of S1 dropped, full density (US 1.07 M S1) | **DMS: US at test density** (62 % of US entities kept, then the SIM19 drop → 0.66 M S1, 5.8 records per S1, like test US); India as SIM19. Ranks, competition features and counts are recomputed inside the universe |
| features | 83 pair features | + 21 transferable features (V5: record ambiguity from the retrieval lists, name specificity, street core); name document frequency is now counted over the S1 **present in the universe** (as on test) |
| stage 1 | XGBoost full + no-embedding, blend 0.75/0.25 (France 0.5/0.5) | same recipe, trained and early-stopped on DMS |
| cross-encoder | XLM-R base on the uncertain band, used by the GNN (V3) | XLM-R base score **plus a second cross-encoder**: `BAAI/bge-reranker-v2-m3` (568 M, Apache-2.0), fine-tuned on V6's own uncertain band [0.01, 0.99]. Both scores are features of the collective rounds (like the "V3 without GNN" stack, the most consistent system in the ablation) |
| stage 2 | context + sibling cosine features (V2) or GNN (V3/V4) | **two collective rounds** (iterative collective classification): context + sibling cosine + **exact sibling evidence** (same / cross source: identical address, shared house number, shared non-S1 number, identical name key, support, confident counts, per-source counts, record-level margin); round 2 recomputes it from round-1 probabilities. **No GNN** |
| calibration | isotonic on SIM19 folds 1-2 | isotonic on DMS folds 1-2 (test density) |
| decoding | expected-F0.5 per S1 | expected-F0.5 per S1 + **per-source caps** (≤ 5 S2, ≤ 6 S3 records per S1, the ground-truth limits) + optional per-country **EM prior correction** + optional France gamma from leave-one-country-out |
| France | 0.5/0.5 blend, same decoder | same + **pseudo-labels** (conservative self-training) if the India→US check says they help |
| choice | V4 rule on SIM19 validation | rule on DMS validation (test density) + US/India consistency gate; fallbacks `final_v3nognn`, V2 |

## 1. Why (measured, not guessed)

* **The leaderboard follows US over-acceptance.** Predicted matches per S1, test/validation, US: V2 +0.95 % →
  LB 0.98332; V3 +2.9 % → 0.98281; V4A +3.5 % → 0.981; GNN alone +9.3 %. India stays within ±0.2 % for all of
  them (phase-2 ablation, your H100 run).
* **Cause: index density.** Test US has 0.66 M S1, train US 1.32 M (India 92 %). With half the competing S1, a
  distractor's best S1 looks "unchallenged", and the competition and count features move. V6 trains, early-stops,
  calibrates and chooses its decoder in a universe with the test's density. The GNN, which reads graph and count
  structure, is dropped. GNNs are known not to generalise across graph sizes when local structure depends on size
  ([Yehudai et al., ICML 2021](https://proceedings.mlr.press/v139/yehudai21a.html)).
* **Recall is the loss.** V3 validation: precision 0.9987, recall 0.9744 (FN 31,722 vs FP 1,629). About 18 k of
  the FN are blocking misses (80 % empty-address records); the rest are scorer misses: house-number changes, new
  names, same-name S1.
* **The generator is hierarchical** (base entity → per-source version → record noise). Same-source siblings share
  81 % identical addresses (record↔S1 76 %). A changed house number is usually shared by the siblings of that
  source. A hard record can be linked through an easy sibling: the collective rounds give the model that evidence
  exactly.
* **Hard limits from the ground truth:** no S1 has more than 5 S2 records (24,154 have exactly 5) or more than 6 S3
  records (2,816 have 6) (`results/eda/eda_report.json`). The decoder enforces them.

## 2. Architecture

```
C2 candidates + 83 pair features (V2 cache, unchanged)
   │
   ├─ density-matched universe DMS (simulate_universe.py): US 62 % of entities, then the SIM19 drop; ranks,
   │  competition features, b_n / a_n / key counts, b_has_match recomputed inside the universe
   ├─ + 21 transferable features (v5/extra_feats.py --absent_code 62): retrieval ambiguity, name specificity over
   │  the universe's S1, street core
   │
   ├─ stage 1: XGBoost full + no-embedding (cross-fitted halves A: folds 1,2 → 0,3,4; B: 3,4 → 1,2), blend
   │
   ├─ cross-encoders on the uncertain band: XLM-R base (V3 scores)  +  bge-reranker-v2-m3 (new, band 0.01-0.99)
   │
   ├─ round 1: context + sibling cosine + collective sibling evidence (from stage-1 p) + both scores → XGBoost
   ├─ round 2: collective evidence recomputed from round-1 p, + prev_p → XGBoost
   │
   └─ isotonic (DMS folds 1-2) → best S1 per record → [EM prior per country] → caps ≤5 S2 / ≤6 S3
      → expected-F0.5 per S1 (France: LOCO gamma if the plan says so) → [France pseudo-labels] → files
```

## 3. Components and the evidence for each

**3.1 Density-matched universe** (`code/v6/simulate_universe.py`, `score_chain.py`). This is the labelled
stand-in for test US. `score_chain` first applies the unchanged V2 chain and the "V3 without GNN" chain to it,
exactly as they run on test (SIM19 calibration). If the test-US over-acceptance reappears there, we can measure and
fix it with labels for the first time. It also reports the **ceiling**: the F0.5 when every true candidate pair is
accepted and nothing else. That is the best any scorer can reach on these candidates. It's reported on the universe
and on SIM19.

**3.2 Transferable features** (`code/v5/extra_feats.py`). They tell the model how ambiguous a record is and how
specific the shared name tokens are, which matters most for France's generic names ("Nantes Club SAS"). Evidence:
attribute-agreement shift is the main failure of learned matchers across datasets
([Beyond Scale and Generation, 2026](https://arxiv.org/abs/2607.24688);
[robustness of PLM matchers, CIKM 2022](https://dl.acm.org/doi/10.1145/3511808.3557673)). Change against V5: counts
now use only the S1 present in the universe, so they're what the test index would show.

**3.3 Cross-encoders: which XLM, and the upgrade.** V3 used `FacebookAI/xlm-roberta-base` (278 M, MIT), fine-tuned
for 2 epochs on the stage-1 uncertain pairs (p in [0.02, 0.98], 981 k train pairs), cross-fitted. Input was raw
"name | address" text in native scripts. On uncertain validation pairs it reached AUC 0.945 against 0.916 for
stage 1. V6 keeps that score and adds `BAAI/bge-reranker-v2-m3`
([model card](https://huggingface.co/BAAI/bge-reranker-v2-m3): Apache-2.0, 568 M, XLM-R-large architecture, distilled
from [BGE-M3](https://arxiv.org/abs/2402.03216) and trained as a multilingual cross-encoder for relevance). Its
pretrained relevance head is kept and fine-tuned on V6's band. Cross-encoders on raw text are the standard strong
matcher ([Ditto, PVLDB 2021](https://arxiv.org/abs/2004.00584);
[Brunner & Stockinger, EDBT 2020](https://openproceedings.org/2020/conf/edbt/paper_205.pdf);
[Peeters & Bizer, PVLDB 2021](https://www.vldb.org/pvldb/vol14/p1913-peeters.pdf)). Generative LLMs mainly help
under schema shift, which we don't have
([Beyond Scale and Generation, 2026](https://arxiv.org/abs/2607.24688);
[Peeters et al., EDBT 2025](https://arxiv.org/abs/2310.11244)).
You can switch models with `XENC2_MODEL`: `FacebookAI/xlm-roberta-large` (MIT, 560 M),
`microsoft/mdeberta-v3-base` (MIT, 280 M; beats XLM-R base by 3+ points on XNLI,
[card](https://huggingface.co/microsoft/mdeberta-v3-base)), or `none`. If the download or training fails, V6
continues with XLM-R base only. It's logged as a WARNING in `results/_runs/v6x_train.log`.

**3.4 Collective rounds** (`code/v6/collective.py`, `train_collective.py`). This is iterative collective
classification ([Lu & Getoor, ICML 2003](https://cdn.aaai.org/ICML/2003/ICML03-066.pdf); collective ER,
[Bhattacharya & Getoor, TKDD 2007](https://dl.acm.org/doi/10.1145/1217299.1217304);
[Rastogi et al., PVLDB 2011](https://arxiv.org/abs/1103.2410)). The evidence is exact and density-free: equality of
normalised address, house number and name key between a record and the S1's other likely records, split by same or
cross source, and weighted by the sibling's probability. Multi-source consistency is also what
[TransClean (2025)](https://arxiv.org/abs/2506.04006) uses to remove false positives. Every input is out-of-fold,
so nothing leaks: siblings belong to the same S1 and therefore the same fold.

**3.5 Decoding** (`code/v6/decode_v6.py`):
* Isotonic calibration ([Zadrozny & Elkan, KDD 2002](https://dl.acm.org/doi/10.1145/775047.775151)).
* Expected-F0.5 per S1 ([Jansche, ACL 2007](https://aclanthology.org/P07-1093/);
  [Nan et al., ICML 2012](https://arxiv.org/abs/1206.4625)).
* Per-source caps: the clean-source and source-consistency idea of multi-source ER
  ([Lerm, Saeedi & Rahm, BTW 2021](https://dbs.uni-leipzig.de/files/research/publications/2021-3/pdf/Paper_MSCD_AP_BTW21_Dresden.pdf)),
  with the limits read from our ground truth.
* Per-country EM prior correction ([Saerens et al., Neural Computation 2002](https://direct.mit.edu/neco/article/14/1/21/6577);
  EM with calibrated probabilities is hard to beat, [Alexandari et al., ICML 2020](https://proceedings.mlr.press/v119/alexandari20a.html);
  [BBSE, Lipton et al., ICML 2018](https://arxiv.org/abs/1802.03916)). It's used only if it fixes the density shift on
  labelled data.

**3.6 France pseudo-labels** (`code/v6/pl_v6.py`). This is conservative self-training: only a confident best S1 with
address agreement, and confident distractors. See [Noisy Student, CVPR 2020](https://arxiv.org/abs/1911.04252) and,
for ER domain adaptation, [DADER, SIGMOD 2022](https://dl.acm.org/doi/10.1145/3514221.3517870). The rule is first
checked on India → US inside DMS (`loco_eval.py`), where labels exist.

## 4. How to run on the H100 (existing cache: V2, V3 and phase 2 done)

```bash
cd <repo>                                     # the folder with run_all.sh, data/cache_v2, results
nohup bash run_all.sh --stage v6all > run_v6.out 2>&1 &
tail -f run_v6.out                            # [run ] / [ ok ] / [skip] per step; logs: results/_runs/<step>.log
```

| block | what | estimate (H100, 32 cores) |
|---|---|---|
| `v6diag` | data probe, V3-without-GNN file, DMS universe, V2 + V3-without-GNN chains on it, ceilings, EM check | 1–1.5 h |
| `v6feat` | 21 transferable features on DMS and test (CPU) | 1–2 h |
| `v6s1` | stage 1 full + no-embedding, blend | ~1 h |
| `v6x` | bge-reranker-v2-m3 fine-tune (2 halves) + out-of-fold scores | 1.5–2 h |
| `v6col` | collective rounds 1 and 2 + decoder search | 1.5–2 h |
| `v6loco` | India → US inside DMS: unseen-country gamma, pseudo-label check | 1–1.5 h |
| `v6test` | stage-1 refits, test band for the cross-encoder, round refits, test scores | 2–2.5 h |
| `v6final` | pre-registered plan + `final_v6` file | ~15 min |
| `v6pl` | France pseudo-labels (only if the plan allows) | ~1.5 h or skipped |
| `v6pick` | validator on every file + choice | ~15 min |

About 11–14 h in total. You need about 150 GB of free disk for the new feature tables and side-car parts.
Options:
* `XENC2_MODEL=none bash run_all.sh --stage v6all` skips the second cross-encoder and saves about 2 h.
* `touch data/cache_v2/_done/v6_loco` before the run skips LOCO and saves about 1.5 h. The plan then uses one gamma
  and no pseudo-labels.
* The V2 recipe at test density (`final_v6a`, an ablation and fallback, about 2 h) is optional:
  `bash run_all.sh --stage v6a`, then `bash run_all.sh --only v6_choose`.

If a step dies, run the same command again: finished steps are skipped. To redo one step, use `--only <step>`.

## 6. Decision rules (fixed before any V6 number exists; `code/v6/choose_v6.py`)

All numbers are on DMS clean folds 0 and 4 (min of the two).
* **caps**: used if they don't lower F0.5 by more than 0.0001. They're true constraints, so they should only help.
* **EM**: used if it raises the V2 chain on DMS by more than 0.001 and lowers no country by more than 0.0005.
* **France gamma**: the LOCO gamma is used if it beats the seen-country gamma on the unseen country by more than 0.001.
* **Pseudo-labels**: used if LOCO shows a gain above 0.001 with pseudo-positive precision ≥ 0.99.
* **Submit V6** if DMS(V6) ≥ max(DMS(V2 chain), DMS(V3 without GNN)) + 0.0005, and the US/India test/DMS ratio of
  predicted matches per S1 exceeds V2's by at most 0.003.
* Order: `final_v6pl` > `final_v6` > `final_v6a` > `final_v3nognn` > V2 (keep).

## 7. About 0.9987 and 0.997: the honest ceiling

* On validation, V3's **precision is already 0.9987**. F0.5 (0.99078) is held back by recall (0.974).
* With the C2 candidates, the best any scorer can reach on SIM19 validation is about 0.997, because blocking misses
  about 1.2 % of true pairs, 80 % of them empty-address records. **F0.5 ≥ 0.9987 on SIM19 validation is not
  reachable with these candidates.** `score_chain_dmsA.json` now measures this ceiling exactly (`ceiling_sim19`) and
  at test density (`ceiling`). With half the competing S1, the test-density ceiling and the achievable score are
  higher, which is probably how 0.997 on the public LB is possible.
* If the DMS ceiling turns out to be the binding constraint, the next step is blocking v3. That means exact-key and
  same-address passes, and all same-key S1 for empty-address records. It needs the feature tables rebuilt (≈ 5 h), so
  it isn't in V6.

Realistic expectations for V6 (public LB):

| target | my estimate |
|---|---|
| > 0.9833 (beat V2) | 70–80 % |
| 0.987–0.990 | 45–55 % |
| 0.990–0.994 | 20–30 % |
| ≥ 0.997 (the current leader) | 5–10 % |

The big unknown is whether DMS reproduces the test shift. `score_chain_dmsA.json` answers that within about 1.5 h
of starting the run.
